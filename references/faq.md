# 元真 FAQ / 避坑指南

> 常见问题速查：文本传不进去、结果不像预期、文件报错时先看这里。

## 1. 怎么把文本传进去？
三种方式任选：`-f 文件.txt`（读 UTF-8 文件）、`--stdin`（管道输入）、直接传文本参数（`yotta-humanize score "这段文字"`）。注意顺序：`score / analyze / report / suggest / rewrite` 子命令 + 输入方式。

## 2. 报「不是 UTF-8 编码」？
把文件另存为 UTF-8 编码再试（记事本 → 另存为 → 编码选 UTF-8）。Windows 的 GBK/ANSI 文件需先转码。

## 3. 文件太大 / 长文处理？
建议分段处理：每段单独 `rewrite` 或 `suggest`，再拼接。复杂长文中的嵌套问题可能需要人工复核，元真只做确定性规则改写，不保证处理所有嵌套句式。

## 4. 改写后变化不大？
说明原文 AI 味本身不高（`score` 低）。先跑 `score` 看评分，再 `analyze` 看命中的规则；确需润色时用 `suggest` 获取人工润色建议，或 `rewrite` 做机械改写。

## 5. rewrite 和 suggest 有什么区别？
`rewrite`：确定性机械改写（命中规则就替换/删除），输出改写后全文 + 修复清单 + 前后评分。
`suggest`：按优先级给改写建议（不直接改原文），适合人工精修。

## 6. CI 拦截怎么用？
`yotta-humanize rewrite --gate --threshold 40`：改写后评分仍 >= 阈值时退出码 1，可在 CI 里拦截 AI 腔内容。`--gate` 需搭配 `score` 或 `rewrite`。

## 7. 退出码 0 / 1 / 4 什么意思？
0 = 成功；1 = `--gate` 命中（评分 >= 阈值，用于 CI 拦截）；4 = 输入错误（文件不存在、无输入等）。

## 8. 会不会改坏原文？
`rewrite` 只做确定性替换/删除（规则命中才动），输出带修复清单（改了什么、改了几处）和 before/after 评分，可逐条核对。不改写事实、数据、专有名词。

## 9. 检测原理是什么？
24 类规则 + 词表（赋能、闭环、值得注意的是、综上所述、希望对你有所帮助 等 AI 常用词与句式）+ 统计突发性，全部确定性规则，不依赖任何模型，结果可复现。

## 10. 边界
只处理文本，不生成新内容；不改写事实 / 数据 / 专有名词；不破坏作者原意。AI 腔极重或嵌套复杂的文本，建议配合人工润色。
